# Readest 自托管版 · 用户手册

> 本手册面向最终用户：讲清楚**服务器怎么部署、账号怎么建、客户端怎么登录使用**。
> 开发者文档见 [README.md](./README.md)。Windows 整合包解压后也有一份 `README.txt`（英文速查），内容与本手册「整合包部署」一节一致。

Readest 自托管版 = **阅读客户端**（桌面 / 安卓 / 网页）+ **你自己的同步服务器**。书库、阅读进度、账号全部存在你自己的机器上，不经过任何第三方云。

- **客户端**：阅读器本体。多个设备登录同一账号即可同步书架与进度。
- **服务端**：`sync-server`（账号 + 同步 + 书库存储，端口 8080）+ 网页端（可选，端口 3000）。桌面/安卓客户端不依赖网页端；网页端只是让浏览器也能读。

---

## 1. 快速开始（Windows 整合包，5 步）

1. 从 GitHub Release 下载 `readest-selfhost-server_*.zip`，解压到任意目录。
2. 双击 **`start.bat`** —— 弹出服务面板窗口，两个服务自动拉起（首次会在目录下创建 `data\` 数据目录）。
3. 在本目录打开终端，创建管理员账号：
   ```
   sync-server.exe add-user <账号> --admin
   ```
   不带 `--password` 时会生成随机密码并**只打印一次**，请立即记录；也可用 `--password 你的密码` 指定。
4. 浏览器打开 `http://localhost:3000`，登录时「服务器地址」填 `http://localhost:8080`，再输入账号密码。
5. 其他设备的桌面/安卓客户端：服务器地址填 `http://<这台电脑的IP>:8080`（局域网需在防火墙放行 **TCP 8080 和 3000**）。

日常使用中 `start.bat` 那个面板窗口保持开着即可；**`q` 或关闭窗口 = 全部服务一起停止**。想开机自启动见 §3.2。

> 账号名**可以是纯用户名**（如 `xiaoming`），也可以是邮箱——两者等价，登录时填什么都能进。

## 2. 客户端下载（GitHub Release 产物对照）

| 产物 | 用途 |
|---|---|
| `Readest_*_x64-setup.exe` | Windows 桌面客户端安装包 |
| `Readest_*_universal.apk` | 安卓客户端（通用包，arm64/x86_64 都可用） |
| `readest-selfhost-server_*_x86_64-pc-windows-msvc.zip` | **Windows 自托管整合包**（服务器 + 网页端一条命令全套） |
| `sync-server_*_<平台>.tar.gz / .zip` | 裸 sync-server 二进制（Linux x64/arm64、macOS、Windows），自建 Docker/系统服务用 |
| `latest.json` | 客户端自动更新清单（一般不用手动下载） |

客户端安装后首次打开，登录页会出现「同步服务器地址」输入框——这就是自托管模式；填你自己服务器的地址即可。

## 3. 服务端部署

### 3.1 三种方式怎么选

| 方式 | 适合 | 一句话 |
|---|---|---|
| **Windows 整合包** | Windows 电脑 / 家里常开的 PC | 解压 → `start.bat`，最省事 |
| **Docker 一键栈** | NAS / Linux 服务器 | `docker compose -f compose.selfhost.yml up -d --build` |
| **裸二进制** | 已有自己的服务管理体系 | 下载对应平台二进制，自己托管进程 |

### 3.2 Windows 整合包

**包内结构**：`readest-supervisor.exe`（入口，守护两个服务）+ `sync-server.exe` + `web\`（网页端）+ `start.bat` / `stop.bat` + `README.txt` + `logs\`，数据落在 `data\`。

- **启动**：`start.bat` 打开服务面板（TUI）。面板里能看到两个服务的状态、内存、延迟、日志尾巴；方向键选服务，`s` / `x` / `r` = 启动 / 停止 / 重启。
- **停止**：`stop.bat`，或面板里按 `q`。服务崩溃会自动重启（指数退避）；连续快速失败会熔断保护，按 `s` 或管理页「服务监控」的「启动」恢复。
- **再次运行**：服务已在跑时再开 `start.bat` 会**附着**到现有实例（不会起第二份服务），`q` 只退出面板、不停止服务。
- **托盘**：默认有托盘图标（启动/停止/重启、开机自启、打开管理页、完全退出）；加 `--no-tray` 参数可关闭。
- **开机自启（无需管理员）**：终端运行 `readest-supervisor.exe install`（注销：`uninstall`）。自启实例无界面运行，托盘 / 管理页都是它的控制面。
- **更高级**：真·Windows 服务（登录前运行）可用 NSSM 包 `readest-supervisor.exe --headless`。
- **升级**：用新 Release 的 `readest-supervisor.exe`、`sync-server.exe`、`web\` 覆盖旧文件即可；`data\` 跨版本兼容，启动时自动迁移。

**防火墙**：给其他设备访问，需放行入站 TCP 8080（同步）和 3000（网页端）。

### 3.3 Docker（NAS / Linux）

```bash
docker compose -f compose.selfhost.yml up -d --build
# 建首个管理员：
docker compose -f compose.selfhost.yml exec sync-server sync-server add-user <账号> --admin
```

- sync-server 在 **8080**，网页端在 **3000**，数据落 Docker 卷。
- 注意构建镜像前 git 子模块要已初始化（`git submodule update --init`）。

### 3.4 配置项（`.env` 文件，放在 exe 旁边；Docker 用 compose 环境变量）

| 变量 | 含义 | 默认 |
|---|---|---|
| `LISTEN_ADDR` | sync-server 监听地址 | `0.0.0.0:8080` |
| `PORT` / `HOSTNAME` | 网页端监听 | `3000` / `0.0.0.0` |
| `DATA_DIR` | 数据目录 | `.\data` |
| `QUOTA_BYTES` | 每用户存储配额 | 2 GiB |
| `ADMIN_TOKEN` | 管理页「服务监控」开关 + 应急 API 令牌（≥8 字符） | 未设则监控页无数据 |
| `READEST_NODE` | node 可执行文件路径（网页端需要 Node ≥ 20） | 取 PATH 里的 node |

## 4. 账号管理

**没有自助注册**：所有账号由管理员创建（命令行或管理控制台），然后把「服务器地址 + 账号 + 密码」发给使用者。账号名**纯用户名或邮箱均可**，系统只把它当作普通标识符。

### 4.1 命令行（在发布包目录执行；Docker 前面加 `docker compose -f compose.selfhost.yml exec sync-server`）

| 命令 | 作用 |
|---|---|
| `sync-server add-user <账号> [--password X] [--admin]` | 建账号。不带 `--password` 生成随机密码（**只打印一次**）；`--admin` 设为管理员 |
| `sync-server passwd <账号> [--password X]` | 改密码。不带 `--password` 会生成随机新密码（**只打印一次**） |
| `sync-server set-role <账号> <admin\|user>` | 调整角色 |
| `sync-server list-users` | 列出账号 |
| `sync-server disable-user <账号>` / `enable-user <账号>` | 停用 / 启用 |

特例：`--password` 后面不跟值（或紧跟另一个参数）= 创建**免密账号**——任何知道账号名的人都能登录，仅适合完全可信的内网，服务端启动时会在日志警告。

### 4.2 管理控制台（网页）

admin 账号登录后：

- 书库页 **设置菜单 →「管理控制台」**；或浏览器直达 `http://<服务器>:3000/admin`（服务端内嵌兜底页在 `:8080/admin`）。

标签页一览：

- **总览**：账号数、书目数、磁盘占用、去重节省、版本与运行时长。
- **用户**：创建 / 删除账号、重置密码（生成的新密码只显示一次）、改角色、停用启用；列表带每账号存储用量与最后活跃时间。
- **书目**：共享书库的书目列表、持有者查看、删除（会移除所有账号的存储副本，确认框会显示影响面）。
- **内容块存储**：回收不再被引用的内容块，释放磁盘。
- **作品归组**：按书名+作者自动归组（走 Open Library，需联网）。
- **服务监控**：两个服务的实时状态 / 内存 / CPU / 延迟，以及启动 / 停止 / 重启按钮（需设 `ADMIN_TOKEN`）。⚠️ 在这里停止 sync-server 会切断面板自身的恢复通道，恢复请回 supervisor 面板或托盘。
- **备份**：一键下载完整备份 tar（数据库 + 全部书目文件 + 登录签名密钥），解包到全新数据目录即可重建服务端。

## 5. 客户端使用

### 5.1 登录

登录页三要素：

1. **同步服务器地址**：如 `http://192.168.1.10:8080`（不用自己加 `http://` 也行，会自动补全）。
2. **账号**：管理员发你的用户名或邮箱。
3. **密码**：免密账号留空直接登录。

登录后书架按**账号隔离**：每个账号看到自己的书。升级后首次登录若书架空了，页面下方会出现「访客书架有 N 本书」的横幅——点「导入」勾选即可把升级前的书并入当前账号（登出后访客书原样保留，导入不复制文件）。

### 5.2 同步与阅读

- 添加书籍、阅读进度、高亮笔记自动同步；换设备登录同一账号即可接续。
- 每用户存储配额默认 2 GiB（`QUOTA_BYTES` 可调），超限时上传会报配额错误，找管理员清理或调额。

### 5.3 会话有效期说明

登录凭据有效期 1 小时，到期能自动续期（前提是设备上保存过密码）。如果你**很久没用后**看到「会话已过期，请重新登录」，重新登录一次即可——服务器一直开着不代表旧登录永久有效；此外若管理员更换了服务器的 `JWT_SECRET` 或清空过数据目录，所有设备都需要重新登录。

## 6. 数据与备份

- **所有数据**（数据库、书文件、登录签名密钥）都在服务器的数据目录里：整合包默认 `data\`，Docker 在数据卷。备份 = 拷走这个目录，或用管理页「备份」下载完整 tar。
- **`data\jwt_secret.key` 是登录签名密钥**：丢失或更换后所有设备必须重新登录（数据本身不丢）。备份时务必包含它。
- 升级服务端只需替换程序文件，**不要动 `data\`**；跨版本自动迁移。

## 7. 常见问题

**客户端提示「无法连接同步服务器」？**
按顺序检查：服务器是否在跑（面板窗口 / `docker ps`）→ 客户端填的地址是否可达（先在浏览器开 `http://<IP>:8080` 应该有响应）→ 服务器防火墙是否放行 8080/3000 → 手机与电脑是否同一局域网。

**提示「账号或密码错误」？**
确认账号密码；连续失败会临时锁定该设备，稍等几分钟再试。忘记密码让管理员在管理控制台重置，或服务器上执行 `sync-server passwd <账号>`。

**提示「会话已过期，请重新登录」？**
正常现象（见 §5.3），重新登录即可。

**端口被其他程序占用？**
`.env` 里改 `LISTEN_ADDR`（如 `0.0.0.0:8081`）和/或 `PORT`（网页端），客户端地址跟着改。

**想公网访问？**
强烈建议套一层 HTTPS 反向代理（如 Caddy/Nginx）再暴露，不要把 8080 裸露公网；客户端地址相应填反代域名。

**书能存哪些格式？**
与上游 Readest 一致：EPUB、PDF、MOBI、AZW3、FB2、CBZ、TXT、HTML 等常见格式。
